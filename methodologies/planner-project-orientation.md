# Planner Project Orientation

For software creation or modification, establish the project workspace inside
the first bounded implementation Worker objective before mutation. Orientation
is context gathering within that implementation work; never represent it as a
standalone plan item, Worker objective, or outcome.

- For an existing project, the same implementation Worker inspects only the
  files or regions needed for the requested mutation, then performs the work.
- For a new project, establish its root as part of the first required
  implementation outcome. When the required artifacts form one connected set,
  create the complete set without a separate bootstrap item.
- When the root's existence is unknown, the same implementation Worker performs
  one bounded check of the exact candidate root, then continues or creates it
  from that observation without returning orientation as separate work.

Consume orientation once, keep every later artifact beneath the established
root, and do not repeat it after the workspace is known. Do not add orientation
to conversation-only or non-persistent requests.
